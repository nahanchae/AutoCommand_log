==================================================
 AirLock PLC Logger 사용 방법
 (PLC 로그 + MSSQL -> PLC 전송)
==================================================

[ 기능 요약 ]
 - PLC 주소를 0.2초마다 읽어서 값 변화 / 입고·출고 / 캐리어 리스트 / RFID 결과를 로그로 남김
 - MSSQL 을 5초마다 읽어서 PLC 로 전송
     R6500 ~ R6503 : FLOW_TYPE = 2 이고 CURRENT_PORT_ID = P1 인 CARRIER_ID
     R6600 ~       : CURRENT_PORT_ID / CURRENT_VEHICLE_ID / TARGET_PORT_ID
                     중 하나라도 값이 있는 CARRIER_ID 목록 (1개당 4워드)
     R6599         : 위 목록의 총 개수
 - 로그 파일 : 로그폴더\plc_log_날짜.txt (하루 1개, 30일 보관)


==================================================
 1. 현장 PC 에 필요한 파일
==================================================

 아래 두 파일을 같은 폴더에 둡니다. (예: C:\ca\AirLock\)

   C:\ca\AirLock\
    ├ AutoCommand.exe
    ├ config.txt
    └ 사용방법.txt (이 파일)

 - config.txt 가 없으면 프로그램이 시작되지 않습니다.
 - log 폴더는 실행하면 자동으로 생깁니다.


==================================================
 2. config.txt 수정 (메모장으로 열기)
==================================================

 [MSSQL]
   DB_IP     = MSSQL 이 설치된 PC 의 IP (같은 PC 면 127.0.0.1)
   DB_PORT   = 1433 (기본값)
   PASSWORD  = DB 비밀번호 입력

 [FILTER]
   SERVER_ID = DB 의 SERVER_ID 값과 정확히 같게
               (첫 글자 대문자 I / 소문자 l 확인)

 [PLC]
   IP / PORT = PLC 주소

 [RUN]
   LOG_DIR   = 로그 저장 폴더 (비워두면 exe 폴더\log)

 ※ config.txt 를 바꾼 뒤에는 프로그램을 껐다 켜야 적용됩니다.
 ※ MSSQL 기능을 쓰지 않으려면 [MSSQL] ENABLE = no


==================================================
 3. 처음 실행 (확인용 - CMD 창 보이는 버전)
==================================================

 처음에는 창이 보이는 exe 로 동작을 확인합니다.
 (빌드 명령: pyinstaller --onefile AutoCommand.py)

 1) AutoCommand.exe 더블클릭
 2) 아래와 같이 나오면 정상

      [START] 프로그램 시작
      [CONNECT] PLC 연결 성공
      [DB CONNECT] 연결 성공
      [CARRIER LIST] ... 전송

 3) [DB ERR] / [PLC ERR] 가 나오면 메시지를 보고 config.txt 수정 후 다시 실행
 4) 확인이 끝나면 Ctrl + C 로 종료


==================================================
 4. 백그라운드 실행 + PC 켜면 자동 실행
==================================================

 1) 창 없는 exe 로 다시 빌드해서 기존 exe 와 바꿔 넣기
      pyinstaller --onefile --noconsole AutoCommand.py
      (dist 폴더 안의 AutoCommand.exe 사용)

 2) 작업 스케줄러 등록
    - Win 키 → "작업 스케줄러" 실행 → 오른쪽 [작업 만들기]

    [일반] 탭
      - 이름 : AirLock PLC Logger
      - "사용자의 로그온 여부에 관계없이 실행" 선택
      - "가장 높은 수준의 권한으로 실행" 체크

    [트리거] 탭 → 새로 만들기
      - 작업 시작 : "시작할 때"

    [동작] 탭 → 새로 만들기
      - 프로그램    : C:\ca\AirLock\AutoCommand.exe
      - 시작 위치   : C:\ca\AirLock

    [설정] 탭
      - "작업이 실패하면 다시 시작" 체크 (1분 간격, 3회)
      - "다음 시간 이상 실행되면 작업 중지" → 체크 해제 !!
        (체크되어 있으면 3일 뒤 자동으로 꺼짐)

    - 확인 → Windows 비밀번호 입력

 3) 바로 시작 : 작업 스케줄러 목록에서 작업 우클릭 → [실행]
    다음부터는 PC 가 켜지면 자동 실행됩니다.

 4) 실행 확인
    - 작업 관리자 → [세부 정보] 탭에 AutoCommand.exe 가 있는지
    - 로그 파일에 줄이 계속 쌓이는지


==================================================
 5. 끄는 방법
==================================================

 - 확인용 (CMD 창 있음)
     창에서 Ctrl + C 또는 창 닫기

 - 백그라운드 (아래 중 하나)
     a) 작업 스케줄러 → 작업 우클릭 → [종료]
     b) 작업 관리자 → [세부 정보] → AutoCommand.exe → [작업 끝내기]
     c) CMD(관리자) → taskkill /f /im AutoCommand.exe

 - 자동 실행까지 완전히 끄기
     위 방법으로 끈 뒤 작업 스케줄러 → 작업 우클릭 → [사용 안 함]

 ※ 백그라운드에서 끄면 [STOP] 로그는 남지 않습니다. (정상)


==================================================
 6. 설정을 바꿨을 때
==================================================

 config.txt 수정 → 위 방법으로 끄기 → 작업 스케줄러에서 우클릭 → [실행]


==================================================
 7. 참고 / 문제 해결
==================================================

 - 이미 실행 중일 때 다시 실행하면 새로 실행한 쪽이 바로 종료됩니다.
   (로그 중복 방지) 설정이 적용 안 되면 기존 프로그램이 켜져 있는지 확인하세요.

 - 작업 스케줄러에서 "로그온 여부에 관계없이 실행" 으로 등록했다면
   DB 로그인은 SQL 인증 (TRUSTED_CONNECTION = no, USER / PASSWORD) 을 사용하세요.

 - 주요 로그
     [START]          프로그램 시작
     [CONFIG ERR]     config.txt 오류 → 내용 확인 후 수정 (프로그램 종료됨)
     [CONNECT]        PLC 연결 성공
     [DISCONNECT]     PLC 통신 끊김
     [RETRY FAIL]     PLC 재접속 실패 (5초마다 재시도)
     [RECONNECT]      PLC 재접속 성공
     [DB CONNECT]     DB 연결 성공
     [DB ERR]         DB 오류 (같은 오류는 1번만 기록, 5초마다 재시도)
     [DB RECONNECT]   DB 재접속 성공
     [PORT CARRIER]   R6500 값 변경
     [CARRIER LIST]   R6600~ 목록 / R6599 개수 변경
     [WARN]           CARRIER_ID 8자 초과 / 목록 최대 개수 초과

 - 문제가 생기면 log 폴더의 plc_log_날짜.txt 를 확인하세요.
